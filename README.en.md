## About

Every day GIT Bot gathers popular and newly rising projects on GitHub into daily, weekly and monthly rankings. Each project gets a Chinese summary, a category and a label saying where the summary came from, so you can quickly tell what it does and whether it's worth trying.

The site is fully static. GitHub Actions collects the data into JSON once a day, and the page reads those files from the same origin. There is no database and no backend service.

The interface is in Simplified Chinese. GIT Bot is built on [NewsNow](https://github.com/newsnext/newsnow) (MIT) and reuses the ranking parser from [GithubTrending](https://github.com/Ibook000/GithubTrending) (Apache-2.0). See [UPSTREAM.md](UPSTREAM.md).

## Features

**Browse**
- Daily, weekly and monthly rankings, plus earlier snapshots by date.
- Two layouts: a card list in ranking order, or a board grouped by purpose.
- One rounded glass card per project: owner avatar, rank and rank change, Chinese summary, language, stars, and stars gained in the period.
- A "爆发" (breakout) badge for projects whose stars gained in the period are large both in absolute terms and as a share of their total.

**Filter**
- Search (⌘K / Ctrl K) across names, summaries, use cases and tech stacks, in Chinese or English.
- Nine categories: AI & agents, developer tools, frontend & UI, self-hosted, data & infrastructure, security & privacy, mobile & desktop, learning & research, and other.
- Filter by programming language. Sort by rank, total stars or stars gained in the period.
- Period, search, language, category and date are kept in the URL, so links can be shared.

**Look and mobile**
- Liquid-glass style with 10 colour themes (6 dark, 4 light), or follow the system's light/dark setting.
- Built for iPhone: floating bottom bar, bottom sheets, safe-area insets. It can be added to the home screen as an app.
- Respects the system's Reduce Motion and Reduce Transparency settings.

**Favourites**
- Saved in the current browser. No account is needed, and nothing is synced to your GitHub stars.

## Where the data comes from

The collector, `collector/collect.py`, runs every day at 00:20 UTC (08:20 Beijing time). For each period it takes data from three sources, removes duplicate repositories and lists them in this order:

| Source | What it contributes | Label on the page |
| :--- | :--- | :--- |
| GitHub Trending (all languages) | The full Trending list, with its original ranks and stars gained in the period | — |
| Language pages | The Trending pages of 12 languages (Python, TypeScript, JavaScript, Go, Rust, Java, C++, C, C#, Swift, Kotlin, PHP); up to 5 projects from each that aren't on the main list | 语言榜 (language) |
| GitHub search | Projects created recently and gaining stars fast: created in the last 7 days for daily, 30 for weekly, 90 for monthly. The top 30 overall, plus up to 8 for each of 8 topics | 新项目 (new) |

GitHub Trending now lists only about 8 to 20 projects per page, so the other two sources supply most of the projects. One run on 2026-10-30 collected 141 daily, 150 weekly and 166 monthly entries: 385 distinct projects.

Categories come from scoring keywords in each project's name, description and GitHub topics. When AI summaries are configured, a validated AI category takes precedence.

A failing source is skipped on its own. If the main Trending list for a period can't be fetched, that period keeps its last complete ranking and the page shows when it was captured. If the very first run fails, the collector stops with an error instead of publishing an empty site.

### Chinese summaries

Each project uses the first available summary from this list, and the page always shows which one it is:

| Order | Source | Label on the page |
| :--- | :--- | :--- |
| 1 | Generated by an AI model from the README, then validated (needs `LLM_*`) | README 解读 (README insight) |
| 2 | Chinese summaries published by GithubTrending (within 7 days) | 中文速览 (Chinese overview) |
| 3 | An initial set written from each project's public description (`collector/editorial.json`), dropped if the description changes | 资料速览 (curated) |
| 4 | A machine translation of the project's own description, via MyMemory's free API | 机器翻译 (machine translation) |
| 5 | Nothing available: the original description is shown | 解读待补充 (pending) |

Machine translations are cached in `public/data/translation-cache.json` by a hash of the description, so each description is translated once. They never replace sources 1 to 3. Template text is never passed off as AI analysis.

## Run locally

Requires Node.js 24 and pnpm 10.30.3. The collector also needs Python 3.12.

```bash
corepack pnpm install --frozen-lockfile
pnpm dev                 # static data mode: reads the JSON in public/data/
```

Collected data is already in the repository, so the front end needs no database or secrets.

```bash
pnpm build:preview       # static build into dist/
pnpm typecheck           # type check (build once first to generate auto-import declarations)
pnpm exec vitest run shared/discovery.test.ts
```

Run the collector:

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r collector/requirements.txt
export GITHUB_TOKEN=your_personal_token   # optional; without it, search runs one overall query per period
python collector/collect.py
python -m unittest discover -s collector -p 'test_*.py'
```

> Collecting locally rewrites `public/data/`. Only the daily collector bot commits that folder, so restore it afterwards with `git restore public/data && git clean -fd public/data`.

## Secrets

The collector runs in GitHub Actions, so secrets go in the **GitHub repository** under Settings → Secrets and variables → Actions, not in Cloudflare. All of them are optional:

| Name | Purpose |
| :--- | :--- |
| `LLM_BASE_URL` | HTTPS endpoint of any OpenAI Chat Completions–compatible API |
| `LLM_MODEL` | Model identifier |
| `LLM_API_KEY` | API key for that service |
| `MYMEMORY_EMAIL` | Contact email for machine translation; raises the free daily quota from 5,000 to 50,000 characters |

With all three `LLM_*` secrets set, the collector reads each README and generates a Chinese summary, use case, tech stack, highlights and category. If a request or validation fails, the existing content is kept. Secrets are never written to the front end or the data files.

The `GITHUB_TOKEN` used for search is provided automatically by GitHub Actions; you don't need to add it.

## Deploy

Production runs on Cloudflare Pages: project `github-discovery`, production branch `main`.

| Setting | Value |
| :--- | :--- |
| Build command | `npx --yes pnpm@10.30.3 install --frozen-lockfile && npm run build:preview` |
| Output directory | `dist` |
| Node version | `24` |
| Database / environment variables | None |

When the collector bot commits new data to `main`, Cloudflare rebuilds the site. The page's refresh button only re-reads the published data; it never starts a collection run.

The original NewsNow Nitro backend (`server/`) is kept. If you need it, `CF_PAGES=1 npm run build` builds the full version; see the [NewsNow README](docs/NEWSNOW-README.md) for its setup. Production doesn't use it.

## Layout

| Path | Contents |
| :--- | :--- |
| `src/components/discovery/` | The home page: cards, filters, themes, details, styles |
| `shared/discovery.ts` | Data format, filtering and validation shared by the page and the collector |
| `collector/` | Collection, categories, Chinese summaries, tests, and the upstream parser |
| `public/data/` | Latest rankings, history snapshots, AI and translation caches |
| `.github/workflows/` | Daily collection and CI checks |
| `server/` | The retained NewsNow Nitro backend |

## Contributing

- `main` is the production baseline. Use `feat/<module>` for features, `fix/<issue>` for fixes and `chore/<task>` for maintenance; merge through a PR once CI passes. See [CONTRIBUTING.md](CONTRIBUTING.md).
- CI ("Discovery checks") runs the full build, type check, data-format tests, collector tests and static build, and uploads a `discovery-static-preview` artifact.
- The data format lives in `shared/discovery.ts`. When you change a field, update the collector output, validation, front end and tests together.
- Only the collector bot commits `public/data/**` directly to `main`.

**Rollback:** the source from before the redesign is kept on the [`backup/radar-before-newsnow-20261026`](https://github.com/chenran71ran-oss/github-discovery/tree/backup/radar-before-newsnow-20261026) branch. To roll back, use Rollback on an earlier deployment in Cloudflare Pages first; no database or domain changes are needed.
